1. Project Overview

ArduSim is a browser-based Arduino/ESP32 circuit simulator. Users write Arduino C++ code in a Monaco editor, drag components onto a canvas, wire them up, and press Run to simulate. The app includes:

  • Monaco Code Editor — VS Code-grade editor with Arduino syntax highlighting and IntelliSense
  • Canvas Circuit Editor — Drag-and-drop component placement with wiring
  • Simulation Engine — Transpiles Arduino C++ to JavaScript and runs it in real-time
  • 33 Components — Arduino Uno, ESP32, LEDs, sensors, displays, ICs, actuators
  • Serial Monitor — Real-time serial output with baud rate control
  • Oscilloscope — Dual-channel waveform viewer
  • Serial Plotter — Real-time data graphing
  • 28 Built-in Examples — From beginner blink to advanced IoT
  • Node.js Backend — Project persistence via SQLite (optional)

3. Architecture & Data Flow

3.1 How the App Starts

  1. index.html loads all CSS and JS files in dependency order
  2. app.js creates an App instance as window.App
  3. App.init() runs this sequence: 
    _initErrorHandlers → _bindUi → _initResizers → _loadTheme →
_initCanvas → _initSerial → _initOutput → _initOscilloscope →
_initPlotter → _attachSimulatorEvents → _renderComponentLibrary →
_renderExamples → _initBoardSelector → GuideManager.bind →
_restoreProject → _setupBeforeUnloadGuard → _syncProjectsFromServer →
EditorManager.init → _initMobile → _hideLoadingOverlay

3.2 How a User Runs Code

  1. User clicks Run (or presses F5)
  2. app.js:run() gets code from EditorManager.getCode()
  3. Calls ArduinoSimulator.run(code)
  4. simulator.js transpiles Arduino C++ to JavaScript
  5. Creates a sandboxed runtime with pinMode(), digitalWrite(), analogRead(), etc.
  6. Runs setup() once, then loop() repeatedly with async delays
  7. When code calls digitalWrite(13, HIGH), the simulator fires onPinChange
  8. canvas.js:updateSimState() receives pin states and updates LED colors, IC outputs, etc.
  9. The canvas re-renders at 60 FPS showing the visual changes

3.3 How Components Are Wired Together

5.3 Simulation: How canvas.js Simulates Components

During simulation, canvas.updateSimState(pinStates) is called every tick. It contains a switch statement on inst.type that handles each component type:

  • Boards — No simulation needed (they produce pin states)
  • LEDs — Read voltage across anode/cathode, compute brightness from runtimeState
  • Buttons — If pressed (interactive property), connect pins to GND
  • Potentiometers — Output analog value based on wiper position
  • Servos — Read PWM signal, update angle
  • DC Motors — Read PWM input, compute RPM
  • Relays — Read signal pin, toggle COM/NO/NC contacts
  • Sensors (DHT11, HC-SR04, LDR, PIR) — Read interactive properties, output values
  • ICs — Evaluate logic gates based on input pins (NAND, NOT, AND, OR, shift register, decoder, bus transceiver)
  • 555 Timer — Astable oscillator with capacitor charge/discharge

6. How to Add a New Component

Step-by-step guide: Follow these steps to add any new electronic component.

Step 1: Choose the right file

Component TypeAdd to File

Step 2: Define the component with defComp()

defComp('my_sensor', {
  name:       'My Sensor',
  category:   'Sensors',
  icon:       '🌡',       // thermometer emoji
  desc:       'Custom temperature sensor',
  width:      80,
  height:     70,
  pins: [
    { id: 'vcc',  label: 'VCC', side: 'top',    type: PIN_TYPE.POWER  },
    { id: 'out',  label: 'OUT', side: 'left',   type: PIN_TYPE.OUTPUT },
    { id: 'gnd',  label: 'GND', side: 'bottom', type: PIN_TYPE.POWER  },
  ],
  defaultProps: { unit: 'C' },
  draw(ctx, inst, defs) {
    const { x, y, width: w, height: h, props, selected } = inst;
    // Draw body
    ctx.fillStyle = '#2d333b';
    roundRect(ctx, x, y, w, h, 4);
    ctx.fill();
    if (selected) { ctx.strokeStyle = '#00e5ff'; ctx.lineWidth = 2; ctx.stroke(); }
    // Draw label
    ctx.fillStyle = '#ccc';
    ctx.font = '10px monospace';
    ctx.textAlign = 'center';
    ctx.fillText('SENSOR', x + w/2, y + h/2 + 4);
    // Draw pins
    drawPins(ctx, inst, defs);
  },
});

Step 3: Add simulation logic to canvas.js

Open js/canvas.js and find the updateSimState(pinStates) method. Add a case for your component in the simulation switch:

case 'my_sensor': {
  // Read interactive property from the component
  const value = inst.props.value || 25; // default 25 degrees
  // Set output pin voltage
  const outPin = inst.pins.find(p => p.id === 'out');
  if (outPin) {
    // Map value to voltage (0-5V)
    const voltage = (value / 100) * 5;
    this._setPinVoltage(inst.id, 'out', voltage);
  }
  break;
}

Step 4 (optional): Add to guide.js

Add documentation in js/guide.js so the help overlay shows your component's description, pinout, and sample code.

Step 5: Test it

  1. Refresh the browser
  2. Find your component in the right panel under its category
  3. Click it, place it on the canvas, wire it up, and run
Important: The component ID you use in defComp() must match the type string used in canvas.js updateSimState() switch statement.

8. How the Simulation Engine Works

8.1 Transpilation (simulator.js)

Arduino C++ is converted to JavaScript via string replacement:

Arduino C++JavaScript
pinMode(13, OUTPUT)_a.pinMode(13, 1)
digitalWrite(13, HIGH)_a.digitalWrite(13, 1)
analogRead(A0)_a.analogRead(14)
delay(1000)await _a.delay(1000)
millis()_a.millis()
Serial.begin(9600)_a.serial.begin(9600)
Serial.println("hi")_a.serial.println("hi")

8.2 Pin State Flow

Arduino code calls digitalWrite(13, HIGH)
    |
simulator fires onPinChange callback
    |
app.js receives it, passes to canvas.updateSimState()
    |
canvas reads pinStates: { 'D13': 5.0, 'D12': 0, 'A0': 2.5, ... }
    |
For each component on canvas, canvas traces wire connections:
  LED anode is wired to D13: pin voltage = 5.0V
  LED cathode is wired to GND: pin voltage = 0V
    |
Canvas computes LED brightness from voltage difference
    |
Canvas re-draws LED with glow effect at 60 FPS

8.3 IC Simulation (in canvas.js)

Digital ICs are simulated by evaluating gate logic each tick:

case 'ic_74hc00': {  // 4x NAND gates
  // Gate 1: pins 1,2 (inputs) -> pin 3 (output)
  const i1 = this._getPinVoltage(inst.id, '1') > 2.5 ? 1 : 0;
  const i2 = this._getPinVoltage(inst.id, '2') > 2.5 ? 1 : 0;
  const out = !(i1 && i2) ? 5 : 0;
  this._setPinVoltage(inst.id, '3', out);
  // Repeat for gates 2,3,4 (pins 4,5->6; 9,10->8; 12,13->11)
  break;
}

11.1 MB102 Power Supply Module

The MB102 is a breadboard-friendly power supply module with selectable voltage rails.

PinSideTypeDescription
vcc_ttopPOWERTop rail voltage output (5V or 3.3V selectable)
gnd_ttopPOWERTop rail ground
vcc_bbottomPOWERBottom rail voltage output
gnd_bbottomPOWERBottom rail ground

Interactive Controls:

  • Power Toggle — ON/OFF switch (inline on front panel)
  • Top Rail Voltage — Dropdown: 5V / 3.3V / OFF
  • Bottom Rail Voltage — Dropdown: 3.3V / 5V / OFF

Simulation: When powered on, the MB102 acts as a voltage source at its output pins. The top rail outputs the selected voltage (5V or 3.3V), and the bottom rail outputs independently. Both rails share common ground.

Usage: Connect vcc_t to your circuit's VCC rail and gnd_t to the ground rail. The MB102 is recognized by _tracePinNet() as a voltage source, so LEDs and other components will light up when connected correctly.

11.2 Benchtop DC Power Supply

A full-featured lab bench power supply with digital display, voltage/current knobs, and binding posts.

PinSideTypeDescription
POSrightPOWERPositive output (0–30V adjustable)
NEGrightPOWERNegative output / ground

Interactive Controls (all inline on front panel):

  • Power Toggle — Master ON/OFF switch
  • Output Toggle — Output ON/OFF (power must be on)
  • Voltage Slider — Range slider, 0–30V (displayed as rotary knob + digital readout)
  • Current Limit Slider — Range slider, 0–5A

Simulation:

  • When output is enabled, POS provides the set voltage (0–30V)
  • Current is calculated from load resistance: I = V / R_load
  • Clamped to the current limit — switches to CC (Constant Current) mode when exceeded
  • Display shows real-time voltage, current, power, and mode (CV/CC)
  • Bulbs blow above 32V (theoretically), but the 12V bulb blows at >16V
Important: The bench supply's _tracePinNet() handler does NOT use continue after pushing sources/grounds. This is intentional — it allows the wire-following code at the bottom of the trace loop to execute, so the trace can leave the bench supply through connected wires. Without this, the supply would appear to have zero current.

11.3 12V Incandescent Bulb

A realistic incandescent bulb with glass envelope, tungsten filament, and Edison screw base.

PinSideTypeDescription
anodetopINPUTPositive terminal (connect to VCC/POS)
cathodebottomOUTPUTNegative terminal (connect to GND/NEG via load)

Simulation behavior:

  • Brightness scales linearly with voltage (0V = off, 12V = full brightness)
  • Blows at >16V — brightness drops to 0, warning logged to Output panel
  • Requires both anode AND cathode wires connected (floating pins = off)
  • Nominal resistance: 12Ω (used for current calculations)
Parallel bulbs: When placing multiple bulbs in parallel, both anode and cathode of each bulb must have external wires. The simulation checks for wire existence before tracing circuits to prevent false glow from internal component leakage.

11.4 How Voltage Sources Are Detected

The simulation engine uses _tracePinNet() to detect voltage sources. A component is recognized as a voltage source if its type is in this list:

  • power_5v — Fixed 5V source
  • battery — Configurable voltage
  • power_supply — Adjustable power supply
  • mb102_power — MB102 module (5V/3.3V selectable)
  • bench_power_supply — Lab bench supply (0–30V)

When a component's anode traces to one of these sources, it receives voltage. The voltage value comes from the source's runtime state or default properties.

12. Electrical Graph Tracer (_tracePinNet)

12.1 How It Works

_tracePinNet(startInstId, startPinId, skipInternalTypes) is the core function that determines electrical connectivity. It uses a breadth-first search (BFS) starting from a given pin and follows wires and component pass-throughs to find:

  • Sources — Voltage sources (5V, 12V, etc.)
  • Grounds — GND connections (0V references)
  • Accumulated resistance — Series resistance along the path

12.2 Trace Algorithm

function _tracePinNet(startInstId, startPinId, skipInternalTypes) {
  queue = [{instId: startInstId, pinId: startPinId, resistance: 0}]
  visited = Set()
  sources = []
  grounds = []

  while (queue not empty) {
    current = queue.shift()
    if already visited: skip
    mark as visited

    // 1. Check component type for sources/grounds
    if Arduino UNO pin → push source or ground
    if ESP32 pin → push source or ground
    if power_5v → push 5V source
    if power_gnd → push ground
    if mb102_power → push source/ground based on rail settings
    if bench_power_supply → push source/ground (NO continue!)
    if LED/IC output → push source if HIGH, ground if LOW

    // 2. Component internal pass-throughs
    if resistor → add other pin with resistance + R
    if push_button → add other pins (when pressed)
    if relay → add COM↔NC or COM↔NO based on state
    if bulb_12v → add cathode from anode ONLY (directional)

    // 3. Follow connected wires
    for each wire connected to current pin:
      queue.push(wire.otherEnd)
  }

  return {sources, grounds}
}

12.3 Directional Pass-Throughs

Most components have bidirectional pass-throughs (current flows both ways). However, the 12V bulb uses a directional pass-through: anode→cathode only.

Why directional? A bidirectional bulb pass-through creates a bridge between separate circuit branches through shared power rails. Example:
LED cathode side (NC) → resistor → bulb cathode → (BULB INTERNAL) → bulb anode
    → POS rail → other bulb anode → (BULB INTERNAL) → other bulb cathode
    → resistor → relay NO side → COM → GND

This path exists regardless of relay state, causing both sides to always find ground. Making the pass-through directional (anode→cathode only) prevents this backward leakage.

12.4 The skipInternalTypes Parameter

When simulating a component, passing skipInternalTypes prevents the trace from entering that component type's internal pass-through:

// Bulb simulation: skip other bulbs' pass-throughs
const anodeNet = this._tracePinNet(inst.id, 'anode', ['bulb_12v']);
const cathodeNet = this._tracePinNet(inst.id, 'cathode', ['bulb_12v']);

// Bench supply: NO skip (needs bulb pass-through for load measurement)
const posNet = this._tracePinNet(inst.id, 'POS');

12.5 Tracing from Power Supplies

Power supply components (MB102, bench supply) do NOT use continue after pushing sources/grounds. This is critical:

// Bench supply handler in _tracePinNet:
if (inst.type === 'bench_power_supply') {
  if (current.pinId === 'POS') sources.push(...)
  if (current.pinId === 'NEG') grounds.push(...)
  // NO continue! Wire-following at bottom must execute
}

Without this, tracing from the supply's own POS pin would find the voltage source but never follow wires to the load, resulting in zero current.

14. Relay Circuit Best Practices

14.1 Relay Pinout

PinDescription
sigControl signal (connect to Arduino digital pin)
vccCoil power (connect to 5V)
gndCoil ground (connect to Arduino GND)
comCommon terminal (connect to power source GND)
ncNormally Closed (connected to COM when relay is OFF)
noNormally Open (connected to COM when relay is ON)

14.2 How the Relay Switch Works

The relay internally connects COM to either NC or NO based on the signal pin:

  • Signal HIGH (relay ON): COM ↔ NO connected, NC disconnected
  • Signal LOW (relay OFF): COM ↔ NC connected, NO disconnected

14.3 Relay Tracing in _tracePinNet

// When relay is OFF (relayOn = false):
COM → NC (pass-through active)
NC → COM (pass-through active)
NO → (blocked, no pass-through)

// When relay is ON (relayOn = true):
COM → NO (pass-through active)
NO → COM (pass-through active)
NC → (blocked, no pass-through)

14.4 Common Relay Circuit Pattern

// Arduino controls relay coil
D9 → relay:sig
5V → relay:vcc
GND → relay:gnd

// Relay switches external load
bench:NEG → relay:com      (power source ground)
relay:nc → load1 → VCC      (load active when relay OFF)
relay:no → load2 → VCC      (load active when relay ON)
Key point: The relay COM pin must be connected to the power source's ground (NEG), NOT to the Arduino's ground. The relay switches a separate high-current circuit independent of the Arduino's logic level.

14.5 Why LEDs Alternate but Bulbs Don't (and the fix)

Problem: LEDs on relay NC/NO alternate correctly, but incandescent bulbs on the same pins glow simultaneously.

Root cause: Bulbs have a bidirectional internal pass-through (anode↔cathode) that LEDs lack. This creates a bridge between NC and NO sides through the shared power rail:

Bulb1 cathode → (internal) → anode → POS rail → Bulb2 anode → (internal) → cathode → NO side

Fix: Bulb pass-through is now directional (anode→cathode only), matching real current flow direction.

15. Simulation Internals & Gotchas

15.1 The updateSimState() Pipeline

Called every simulation tick via _render():

  1. Update relay states from Arduino pin values
  2. Update IC outputs from input pins (74HC series, 555 timer)
  3. Update LED brightness from voltage across anode/cathode
  4. Update bulb brightness from voltage across anode/cathode
  5. Update servo angle from PWM signal
  6. Update DC motor speed from PWM signal
  7. Update sensor outputs (DHT11, HC-SR04, LDR, PIR)
  8. Update bench supply current from load resistance
  9. Update wire colors based on voltage

15.2 Standalone Power Detection

When no Arduino sketch is running, the simulator checks for standalone power components:

const standaloneTypes = new Set([
  'power_5v', 'power_gnd', 'mb102_power',
  'bench_power_supply', 'func_gen'
]);
this._hasStandalonePower = this.components.some(c => standaloneTypes.has(c.type));

If standalone power exists, updateSimState({}) is called even without ArduinoSim.isRunning. This allows LEDs and bulbs to light up when connected only to bench power supplies.

15.5 Service Worker Caching

The service worker (sw.js) caches all static files. When modifying JS files:

  1. Bump the cache version in sw.js (e.g., ardusim-v7 → ardusim-v8)
  2. Bump the ?v= query string in index.html for changed scripts
  3. Users must hard-refresh (Ctrl+Shift+R) to pick up changes
Cache version bump checklist:

3. Test with hard refresh before deploying

15.6 Adding Simulation Logic for New Components

When adding a new component that needs simulation:

  1. Add case 'my_component': in updateSimState() switch
  2. Use _tracePinNet(inst.id, 'pinId') to find voltage sources and grounds
  3. Check sources.length > 0 and grounds.length > 0 for complete circuit
  4. Calculate voltage from sources[0].voltage and resistance from accumulated values
  5. Update inst.runtimeState with visual state (brightness, angle, speed, etc.)

16. Remote Control (Phone Control)

ArduSim supports controlling your simulated circuit from a phone on the same network. This uses a public MQTT broker (HiveMQ) to relay pin commands between the phone and simulator — no app install required.

How It Works

Phone (browser)  ←→  HiveMQ Broker (WSS)  ←→  Simulator (browser)
   publish pin           public broker           subscribe & apply
   commands              port 8884               via setPinState()

Step-by-Step Usage

  1. Build your circuit and write your Arduino sketch
  2. Click Run to start the simulation
  3. Click the Remote button (phone icon) in the header
  4. A modal shows your Session Code (e.g., x7k2m) and a URL
  5. Copy the URL and open it on your phone's browser
  6. Use the phone interface to toggle digital pins, adjust analog sliders, and send serial messages
Tip: Both devices must be on the same network (WiFi). The phone page connects directly to the public MQTT broker — no server configuration needed.

Phone Interface Features

FeatureDescription
Digital Pin Toggles (D0-D13)Tap to set pin HIGH (1) or LOW (0)
Analog Sliders (A0-A5)Slide to set value 0-1023
PWM Sliders (D3,D5,D6,D9,D10,D11)Slide to set duty cycle 0-255
Serial MonitorSend text to the Arduino's Serial input
Pin State DisplayShows real-time pin values from the simulator

Technical Details

  • MQTT Broker: HiveMQ public broker at wss://broker.hivemq.com:8884/mqtt
  • Topics: All topics are namespaced with a random session ID to prevent cross-user interference
    • ardusim/cmd/{session} — Phone sends pin/serial commands
    • ardusim/pin/{session} — Simulator publishes individual pin changes
    • ardusim/state/{session} — Simulator publishes full state snapshots
    • ardusim/serial-out/{session} — Simulator publishes serial output
  • Separate MQTT client: The remote control uses its own MQTT connection, separate from any MQTT used in your Arduino sketch
  • Security: Commands are unauthenticated. Use only on trusted networks.

Example Sketches

Two example projects demonstrate remote control:

  • Remote Control LEDs — Toggle 4 LEDs (D2-D5) from your phone
  • Remote Servo Control — Use the A0 slider to control a servo motor angle

Creating Your Own Remote-Controlled Project

// Read pins that the phone controls
int led1 = digitalRead(2);  // D2 toggle on phone
int led2 = digitalRead(3);  // D3 toggle on phone

// Use analog values from phone sliders

servo.write(map(angle, 0, 1023, 0, 180));

// Send data back to phone
Serial.println("Hello from Arduino!");
Limitation: The phone can only write to pins that are configured as INPUT in your sketch. Make sure to use pinMode(pin, INPUT) for pins you want to control remotely.

16. How to Add a New Library (Plugin System)

ArduSim supports Arduino libraries through a plugin system. You can add support for any new Arduino library without editing simulator.js. Just drop a .js file in the js/libraries/ folder.

16.1 How It Works

Each library plugin is a JavaScript file with up to 5 properties:

  • classes — C++ class names to auto-detect (e.g., ['MyClass'])
  • transpile — Regex rules converting Arduino C++ to JavaScript
  • runtime(self) — Functions merged into the _a object (actual simulation logic)
  • constructor — What new ClassName() returns (set to null if it needs self)
  • constants — Global constants (e.g., DHT11, SSD1306_WHITE)

16.2 Plugin File Format

// js/libraries/mylibrary.js
window.ArduinoLibs = window.ArduinoLibs || {};
window.ArduinoLibs['MyLibrary'] = {

  // Class names this library provides
  classes: ['MyClass'],

  // Transpile rules: [regex, replacement]
  transpile: [
    [/\.myMethod\s*\(/g, '._myMethod('],
    [/\.getValue\s*\(\s*\)/g, '._getValue()'],
  ],

  // Runtime functions — merged into _a object
  // 'self' is the ArduinoSimulator instance
  runtime: function(self) {
    return {
      _myMethod: function(arg) {
        self._serialLog('[MyLib] myMethod(' + arg + ')\n', 'system');
      },
      _getValue: function() {
        return 42;
      },
    };
  },

  // Constructor — what `new MyClass(args)` returns
  // Set to null if constructor needs 'self' (stays in simulator.js)
  constructor: function(args) {
    return {
      myMethod: function(arg) {},
      getValue: function() { return 42; },
    };
  },

  // Constants — injected as global variables
  constants: {
    MY_CONST_A: 100,
    MY_CONST_B: 0xFF,
  },
};

16.3 Step-by-Step: Adding a New Library

Step 1: Create the plugin file

Create js/libraries/mylibrary.js with the format above.

Step 2: Add script tag to index.html

Add this line before the simulator.js script tag:

<script src="js/libraries/mylibrary.js?v=20260904-1"></script>

Step 3: Use it in Arduino code

#include <MyLibrary.h>

MyClass myObj(42);

void setup() {
  Serial.begin(9600);
  myObj.myMethod("hello");
}

void loop() {
  int val = myObj.getValue();
  Serial.println(val);
  delay(1000);
}

Step 4: Refresh and run

Refresh the browser. The simulator will automatically detect MyClass and use your plugin.

No simulator.js edits needed! The plugin system auto-loads all .js files from js/libraries/ at startup.

16.4 The runtime(self) Pattern

The runtime(self) function receives the ArduinoSimulator instance and returns functions that get merged into the _a object. This gives plugins full access to simulator internals:

runtime: function(self) {
  return {
    // Access serial logging
    myFunc: function() {
      self._serialLog('[MyLib] message\n', 'system');
    },

    // Emit events to canvas
    myShow: function() {
      self._emitEvent('my_event', { data: 123 });
    },

    // Access pin states
    readPin: function(pin) {
      return self.pinStates['pin_' + pin] || 0;
    },

    // Async functions (for delays, animations)
    myAsyncFunc: async function(obj) {
      await self._delayPromise(1000);
      self._serialLog('[MyLib] done\n', 'system');
    },
  };
},

16.5 When to Use constructor: null

If your constructor needs access to self (e.g., to read from CircuitCanvas or emit events), set constructor: null and keep the constructor in simulator.js:

// Plugin file
window.ArduinoLibs['MySensor'] = {
  classes: ['MySensor'],
  transpile: [...],
  runtime: function(self) {
    return {
      // _a.* functions that use self
    };
  },
  constructor: null, // Stays in simulator.js because it needs self
  constants: {},
};

Constructors that DON'T need self can be defined in the plugin:

constructor: function(args) {
  return {
    begin: function() {},
    read: function() { return 42; },
  };
},

16.6 Transpile Rules Explained

Transpile rules are [regex, replacement] pairs that transform Arduino C++ code to JavaScript.

Arduino C++RegexReplacementJavaScript Output
gps.encode(c)/\.encode\s*\(/g._encode(gps._encode(c)
gps.location.lat()/\.location\.lat\s*\(\s*\)/g._lat()gps._lat()
SPI.transfer(data)/\bSPI\.transfer\s*\(/g_a.spiTransfer(_a.spiTransfer(data)

16.7 Advanced: Variable-Name Prefix Matching

Some libraries need to match only specific variable names. Use a function callback:

transpile: [
  [/\b(\w+)\.begin\s*\(\s*\)\s*;/g, function(m, v) {
    if (/^(bme|sensor|bmp)/i.test(v)) return '_a.bme280Begin(' + v + ');';
    return m; // Leave other .begin() calls alone
  }],
]

17. Wi-Fi Hotspot Module & Wi-Fi Projects

17.1 What is the Wi-Fi Hotspot?

The Wi-Fi Hotspot component (found in the Communication category) is a simulated wireless access point. The ESP32 must match this component's SSID and password to connect to WiFi. Without this component on the canvas, WiFi.begin() will fail with "SSID not found".

Important: Every WiFi-related project (MQTT, HTTP, NTP, I2S streaming, etc.) requires a Wi-Fi Hotspot component on the canvas. All WiFi examples in the Examples panel already include one.

17.2 Properties

17.3 Quick Start: Connect ESP32 to Wi-Fi

  1. Place an ESP32 DevKit V1 board on the canvas
  2. Place a Wi-Fi Hotspot component (Communication category → search "wifi")
  3. Set the hotspot's SSID and Password in the properties panel
  4. Write your Arduino code using matching credentials:
#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  WiFi.begin("ArduSim_Network", "password123");

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("Connected!");
  Serial.println(WiFi.localIP());
}

void loop() {}
Tip: If the hotspot's Gateway IP is 192.168.1.1, the ESP32 will be assigned 192.168.1.105.

17.5 WiFi Scan Example

This example scans for all Wi-Fi Hotspot components on the canvas and prints their details:

#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.disconnect();
  delay(100);

  Serial.println("Setup done");
}

void loop() {
  Serial.println("Scanning for networks...");
  int n = WiFi.scanNetworks();
  Serial.println("Scan complete");

  if (n == 0) {
    Serial.println("No networks found.");
  } else {
    Serial.print(n);
    Serial.println(" networks found:");
    for (int i = 0; i < n; ++i) {
      Serial.print(i + 1);
      Serial.print(": ");
      Serial.print(WiFi.SSID(i));
      Serial.print(" (");
      Serial.print(WiFi.RSSI(i));
      Serial.print(" dBm) Channel: ");
      Serial.print(WiFi.channel(i));
      Serial.print(" Encryption: ");
      switch (WiFi.encryptionType(i)) {
        case WIFI_AUTH_OPEN:  Serial.println("Open"); break;
        case WIFI_AUTH_WPA2_PSK: Serial.println("WPA2"); break;
        default: Serial.println("Unknown"); break;
      }
      delay(10);
    }
  }
  Serial.println("");
  delay(5000);
}
Note: Add multiple Wi-Fi Hotspot components to the canvas with different SSIDs to simulate scanning multiple networks.

17.6 WiFi + MQTT Example

Most IoT projects combine WiFi with MQTT. Place a Wi-Fi Hotspot, then connect to MQTT after WiFi:

#include <WiFi.h>
#include <PubSubClient.h>

const char* ssid     = "ArduSim_Network";
const char* password = "password123";
const char* mqtt_server = "broker.hivemq.com";

WiFiClient espClient;
PubSubClient client(espClient);

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("WiFi connected");

  client.setServer(mqtt_server, 1883);
  client.connect("ArduSim_ESP32");
  if (client.connected()) {
    client.publish("ardusim/status", "online");
    Serial.println("MQTT connected");
  }
}

void loop() {
  client.loop();
}
